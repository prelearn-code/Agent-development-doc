### 目标7：执行器、固定审批与密码业务（30h）

**进入条件**：V3一个只读MCP闭环通过，V2持久化与权限稳定。V4先用20h实现一种审批加密与工具结果证据；V6用10h补轮换/CSR/签发及≥50题。RAG引用不是前置。

**Agent目标**：将模型提议升级为受控写动作，审批绑定准确资源与版本。 对应详细任务：**M4 01–06**。

**技术点掌握程度标准**

| 风险/执行入口 | 只读、敏感读取、写与破坏风险不同 | 校验→授权→审批→intent→Provider→输出→审计 | 模型/MCP注解不能降风险，默认不导出/销毁私钥 | 拒绝与审计证据 | 任意代码执行 |
| Approval/Action | 审批固定hash，不是授权整段对话 | 绑定身份/参数/工具/资源/策略版本和期限 | 变更、重放、重复/并发决定不得二次授权 | hash对照与单次消费 | 多级审批组织流程 |

**学习与实现顺序**：ToolSpec/policy → action_hash → 审批API/账本 → 一个受控写动作 → 密钥版本/证书流程 → 工具评测。先一动作闭环再增加数量，业务深度按06表格。

**必须独立回答**：敏感解密为什么不是普通只读？旧批准能否用于新参数？请求重传和自动重试写动作有什么区别？

**独立练习**：更换资源版本使旧审批失效；比较提议遭拒与实际越权；核对轮换后真实key version。

**退出条件**：已开放工具满足密码业务参考标准，写动作与敏感解密固定审批，≥50工具题可复现，结果与实际产物一致。

**独立练习**：审批后更改有效期或 SAN。证明旧审批不能执行新参数，并指出新审批为什么不同。

**Agent目标**：工作流持久化暂停与恢复，控制流和外部副作用分别管理。设计见07。 对应详细任务：**M4 12–16**。

本项目 `thread_id=run_id`，每次请求一个工作流；聊天历史显式加载。动态审批使用锁定版本的 `Command(resume=...)`，图恢复会重入节点，不能把无幂等的签发放在可重复执行的位置。参见 [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)。

动作状态采用 proposed→awaiting_approval→ready→executing→succeeded/failed/cancelled/unknown。若证书已签发但 DB 结果未提交，重启必须依据 action/job/idempotency 核对，不能再签一张。无法确认时进入 unknown/reconciling，明确要求核对。

第一个 Verify 节点先验证输出结构、必要动作成功与证据存在；完整事实验证在 M5。取消与断线分开；网页断线不改变 pending approval，也不撤回已经完成的密码操作。

**独立练习**：针对一个轮换流程指出每个副作用发生点，演示任一节点重入时如何避免重复；状态机和判断由你设计，AI 审查。

**进入条件**：V4先用5h核对工具最终状态/产物/版本；V5有真实引用后用10h完成六检查与正误双集。核心检查与反例本人编写。

**Agent目标**：区分模型文本与可验证结果，让已验证结论有事实依据。 对应详细任务：**M5 Verifier 六检查**。

| 事实槽与资源绑定 | 将事实绑定 subject/entity、字段、值、单位、来源和版本，不只搜索答案中是否有某个数字 | A/B 证书日期互换、错误 key version 等样本被识别，正确样本通过 | 任意自然语言事实的完全自动证明 |
| 引用存在与支持关系 | 分开来源存在、定位有效、来源是否支持结论；权限与版本均核对 | 存在但不支持的引用被标错；“解析成功→链可信”不能通过 | 全自动开放域事实核查 |
| 修复、阻断与展示状态 | 定义哪些错误可有限修复、哪些必须阻断；失败不包装为 verified 成功 | 错误结果与前端/最终回答一致，修复循环有次数上限 | 复杂生成式裁判与自动协商 |
| TPR/FPR 与独立样本 | 自己审定至少 20 正确、20 错误样本，列混淆矩阵；说明检错率与误伤率分母 | 手算小例子再核对脚本，逐条保存检查依据和误判原因 | 大规模自动合成 gold；仅用模型评价自身输出 |

| 检查 | 密码业务中核对什么 | 典型失败 |
|---|---|---|
| 必要工具状态 | 需要的最终动作是否 succeeded | 工具失败但回答已加密成功 |
| 事实绑定 | key/cert/file/provider/version 与数值是否一致 | 把 A 证书的日期写成 B 的日期 |
| 密码结果 | 摘要、认证、签名验证与实际返回一致 | verify=false 却回答签名有效 |
| 引用存在与定位 | 文档版本、章节/页码与授权 | 引用不存在或过期证据 |
| 引用支持与无支持结论 | 来源是否支持对应解释 | 只解析证书却声称证书链可信 |
| 输出结构与展示状态 | final/schema/verified 状态 | 未检查项被当作已通过 |

任务：先验证结构与工具状态，再验证 subject/metric/value/unit/source_ref 的绑定，最后验证语义。摘要按字节/编码规范比对，日期/serial/key_id 按各自类型处理，不能把所有字符串强行小写；计算到期天数记录时钟与公式。历史一次失败后重试成功不应永久阻塞任务，但不能忽略尚未完成的必要检查。

**验收指标**：至少 20 个已知错误与 20 个已知正确回答初测；报 TPR=检出的错误/错误样本，FPR=误拦正确回答/正确样本，并列漏报/误报与样本数。确定性高风险事实错报应阻塞发布。语义指标先测再定目标，不把小样本百分比当总体保证。

**独立练习**：构造“数字本身正确但属于另一张证书”的回答，证明仅检查数字集合无法发现它，再自己补事实绑定。

### 目标14：Agent 安全与实际边界（20h）

**进入条件**：基本授权/秘密/超时从V1贯穿。V4用5h专门验证写动作边界，V6用15h完成本人威胁模型、完整攻击面与发布回归。

**Agent目标**：模型即使受到注入，实际资源仍受服务端边界保护。 对应详细任务：**M5 Security 威胁模型与回归**。

**技术点掌握程度标准**

| 技术点 | 能解释 | 独立做到 | 排错与边界 | 验收证据 | 后置内容 |
|---|---|---|---|---|---|
| 威胁模型 | 用户、文档、模型、MCP、秘密信任不同 | 本人列资产/入口/攻击路径/防护/残余风险 | prompt分隔与输入检测只是辅助 | 自绘边界图与风险表 | 全面红队平台 |
| 执行安全 | schema不等于授权，UUID不等于权限 | 本人验证命令/路径/SQL/SSRF与跨用户边界 | 模型被注入仍不能越过执行器 | 拒绝审计及真实资源/网络断言 | 任意shell沙箱 |
| 审批/Memory/MCP | 历史同意与外部声明不能自授权 | 本人设计重放/参数变更/annotation/投毒测试 | 检查副作用而非只看回答说拒绝 | 各关键面证据 | 公网不可信工具 |

**学习与实现顺序**：资产/边界 → 本人设计隔离教学测试 → 实际状态检查 → 回归 → 缺口记录。文档不代写对抗测试实现。

**必须独立回答**：尝试越权被拒为何不同于实际越权？UI隐藏按钮为什么不是授权？哪里可能意外记录秘密？

**独立练习**：从本人一条攻击输入追踪到拒绝点与审计，确认隔离资源未改变。

**退出条件**：有效Security场景实际越权率0，失败门禁不可豁免；有限测试不构成生产安全保证，V6完整专项通过后标记m5-done。

**具体实践与逐项操作**


基础安全从V1贯穿；V4专用5h由本人验证固定审批、参数/资源变更、重放、下载/秘密和实际副作用，V6用15h完成全威胁模型与攻击面。本人编写核心对抗测试，AI只审查。

学习威胁模型、直接/间接注入、参数注入、路径、SSRF、跨用户访问、秘密脱敏、审批重放、MCP 信任和 Memory 投毒。安全用例按实际攻击面由你自行设计，AI 审查；下面给出检查维度，不代写实现仓库的攻击测试代码。

**技术点掌握程度标准**

| 技术点 | 本阶段必须能独立做到 | 练习与验收证据 | 可后置内容 |
|---|---|---|---|
| 威胁模型与信任边界 | 画用户输入、模型、文档、MCP、执行器、DB/keystore 的边界，列出资产与实际入口 | 自己写风险→控制→证据映射，能说明控制由哪个模块强制执行 | 企业安全认证与全套合规体系 |
| 直接/间接注入与 Memory 投毒 | 外部文本仅是数据；不能修改工具策略、审批身份或记忆写入权限 | 自己设计入口相关样本，用实际执行与记忆状态验证，不只看回答拒绝 | 开放域攻击生成研究 |
| 路径与参数注入 | 由服务端解析获授权资源，控制输出目录；固定 CLI 参数，模型不能插入 shell 或切换任意程序 | 拒绝记录与实际文件/进程状态，说明软链接和规范化边界 | 复杂文件存储隔离 |
| SSRF 与连接信任 | 有网络入口时限制可连接目标与重定向等路径；没有入口时记录不适用，不凭 prompt 授权 | MCP/URL 配置的允许与拒绝证据；部署网络与应用策略对应 | 通用网络扫描与渗透工具体系 |
| 身份、资源授权与下载 | 每次执行、查询和下载都校验身份与资源范围；前端隐藏按钮不能替代后端鉴权 | 两用户场景中 denied 与 executed 分开，越权请求无实际副作用 | 企业复杂 RBAC/ABAC 策略引擎 |
| 秘密处理与最小暴露 | 逐项追踪 key/口令/明文在存储、消息、日志、错误和 artifact 的流向 | 受控测试秘密的泄露检查及授权下载记录，解释应用进程仍可访问什么 | HSM、远程证明、内存取证 |
| 审批重放与安全计量 | 固定动作、一次消费、版本和并发约束有效；Unauthorized Action Rate 用实际越权动作计量 | 自己设计重放/竞争场景，实际越权动作数为 0；报告用例范围，不宣称绝对安全 | 生产安全认证与无限攻击覆盖 |

| 边界 | 要验证的行为 | 验收证据 |
|---|---|---|
| 文件 | 模型不能越过授权范围读取或写入 | 实际文件快照与执行审计 |
| 密钥 | ID 可见，密钥值/口令不进入消息与日志 | 受控测试秘密的泄露检查 |
| 解密 | 必须授权具体文件、密钥版本与输出位置 | 审批、输出 artifact 归属与下载权限 |
| 证书签发 | SAN/有效期/用途/CA 权限程序校验 | 实际证书字段与动作记录 |
| 工具执行 | 参数数组与固定入口，无通用 shell | adapter 配置与拒绝行为 |
| 工作流 | 重放/改参数/并发审批不能扩大授权 | action_hash、消费状态、执行计数 |
| 检索与 MCP | 外部内容不改变本地权限 | denied/executed 与实际状态 |

**硬门槛**：实际 Unauthorized Action Rate=0，且逐例无越权副作用；日志/Trace/UI 没有测试密钥与口令泄露；高风险操作不绕过审批；确定性安全回归全部通过。有限测试的 0 不等于系统不存在任何漏洞。

本项目只开放已登记的密码与知识工具，禁止任意代码执行；Provider的参数、进程清理和结果发布都由执行器控制。

### 第一种写动作的步骤与出口

1. 直接完成M1 06：固定profile、≤1MiB教学文件，字节往返、改密文认证失败；密钥/明文不回模型。
